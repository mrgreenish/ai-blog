# Spec: [feature or component]

## Overview
What should this do, and for whom?

## Inputs
List props, user actions, and data dependencies.

## Outputs
Describe rendered UI, return values, or side effects.

## Behaviour / Logic
Describe the rules in terms a reviewer can verify.

## Constraints
Record compatibility, accessibility, performance, and project conventions.

## Edge Cases
List empty, invalid, loading, and failure states that apply.

## Acceptance Criteria
- Given [starting condition], when [action], then [observable result].

## Not in scope
Explicitly exclude adjacent changes.

## Verification
Commands and manual checks that demonstrate the behaviour.
